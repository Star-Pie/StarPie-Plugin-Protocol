# 动作执行路径

## 1. 定位与当前状态

动作执行路径处理“用户已经选定一个功能，现在执行它”的请求，例如启动程序、发送快捷键、调整设备状态或调用外部工具。

| 项目 | 结论 |
|---|---|
| 当前成熟度 | 主要注册、配置和调用链已经存在，接近可用 |
| 实现难度 | 低，三条路径中最低 |
| 可行性 | 很高 |
| 性能表现 | 最好；正确使用后台调度时不影响轮盘交互 |
| 开发推荐度 | 当前应优先完善                           |

插件清单声明：

```json
"paths": ["action-execution"]
```

## 2. 当前调用方式

当前实现已经形成以下路径：

```text
插件 Initialize
→ context.Actions.Register(contribution)
→ 注册会话暂存动作
→ Initialize 成功后提交到 PluginCatalog
→ 设置页从 Catalog 列出可用动作
→ 用户配置保存 Type="Plugin" 和 PluginActionRef
→ 轮盘命中后 ActionExecutor 转交 PluginHost
→ PluginInvoker 按 Sequential 或 Background 执行
→ 插件返回 ActionResult
```

动作引用分别保存：

```text
PluginId       = com.example.hello
ContributionId = greet
FullId         = com.example.hello.greet
```

宿主通过注册目录查找贡献，不根据配置反射插件方法。

## 3. 计划稳定的调用规约

```text
轮盘提交动作
→ 生成不可变动作请求
→ 按 FullId 查询已提交贡献
→ 必要时加载并启用插件
→ 校验启用、隔离和能力状态
→ 使用统一入口校验参数
→ 获取活动调用租约
→ 根据动作调度类别执行
→ 规范化结果并记录健康状态
→ 任务真实结束后释放租约
```

### Sequential

只用于短小且必须保持顺序的操作。网络、目录遍历、COM、DDC/CI 等不确定耗时工作不得进入串行动作线程。

### Background

耗时或 IO 动作必须后台执行。后台任务不能阻塞轮盘关闭，并且租约必须保持到真实任务结束。

## 4. 当前主要问题

1. **惰性加载顺序**：当前执行入口存在先查询 `Catalog`、再尝试惰性加载的风险。重启后未预加载插件可能因为目录中还没有动作而无法触发加载。
2. **后台动作租约**：后台动作必须在整个异步任务期间计入活动调用，不能在排队后立即释放，否则停用可能与执行竞态。
3. **结果类型不足**：当前结果主要表达成功或失败，后续应明确区分成功、环境不可用、取消、超时和插件故障。
4. **并发策略未完整统一**：同一动作的允许并发、串行、忽略重复和替换旧任务仍需形成宿主规则。
5. **停用竞态**：插件进入停止状态后必须拒绝新动作，并等待已取得租约的动作结束。
6. **完整 ID 兼容**：协议和实现必须统一使用点号格式，不再引入斜杠格式。

## 5. 接下来修改方向

### 第一阶段：修正执行接缝

- 执行前先根据 `PluginActionRef.PluginId` 确保插件已加载，再查询完整动作 ID。
- 将参数保存校验和执行校验收敛到同一个宿主入口。
- 为 Sequential 和 Background 建立一致的活动调用租约。
- 停用时先关闭新调用入口，再取消并等待运行中动作。

### 第二阶段：完善结果和并发

- 增加成功、拒绝/不可用、取消、超时、故障等标准结果。
- 增加动作并发策略，由宿主执行而不是插件自行加全局锁。
- 仅将真正的插件缺陷计入连续失败和隔离。

### 第三阶段：补齐自检

- 覆盖重启后首次惰性调用。
- 覆盖后台动作执行期间停用插件。
- 覆盖参数正反例、超时、取消和环境不可用。
- 验证配置引用、下拉选择和运行时查询使用同一完整 ID。

## 6. 修改难点

动作路径的主要难点不在接口设计，而在生命周期一致性：

- 异步任务何时算真正结束；
- 停用和新调用如何原子切换；
- 超时后任务仍可能继续运行；
- 环境不可用不能错误触发插件熔断；
- UI 保存与运行时执行不能使用两套参数规则。

这些问题可以在现有结构上修正，不需要重新设计整个轮盘核心。

## 7. 插件开发规则

- 动作短 ID 发布后保持稳定。
- 参数使用声明式字段，不提供自定义 XAML。
- 布尔值 `false` 必须显式保存，数字使用区域无关格式。
- 环境条件不满足返回拒绝/不可用，不要一律返回失败。
- 耗时动作声明为 Background。
- 插件必须监听取消信号；超时不等于线程已经停止。
