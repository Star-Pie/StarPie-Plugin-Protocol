# 运行时与生命周期

## 1. 加载流程

```text
静态扫描
→ 校验清单、目标框架和架构
→ 创建独立可回收加载上下文
→ 加载入口程序集
→ 创建插件入口对象和宿主上下文
→ Initialize 暂存注册
→ 验证并统一提交
→ 插件进入 Active
```

扫描阶段不得执行插件代码。SDK 契约程序集必须由宿主共享，不能从插件目录加载第二份。

“用户已启用”和“当前进程已加载”是两个状态。宿主可以让已启用插件保持未加载，等第一次真实请求时再惰性加载。

## 2. 线程规则

- 插件不得假设回调发生在 UI 线程。
- 插件不得直接操作宿主窗口和 WPF 对象。
- 输入 Hook 只负责采集状态，不在其中执行插件代码。
- 交互事件应通过独立队列投递。
- 轮盘结构查询不得阻塞轮盘显示；超时使用缓存或静态回退。
- 耗时动作必须使用后台调度，不能占用动作串行线程。

## 3. 活动调用租约

每次进入插件实现的回调都必须计为活动调用，包括：

- 动作自定义参数校验；
- 动作预览；
- 动作执行及其后台任务；
- 交互事件回调；
- 轮盘结构查询。

活动调用租约由宿主自动管理，不属于插件 SDK。插件作者不获取、不保存也不释放租约。

插件需要保证：

```text
ExecuteAsync 返回的 Task
= 本次动作真实工作的生命周期
```

不应这样实现：

```text
ExecuteAsync 内启动未等待的长期 Task
→ 立即返回成功
```

否则宿主会认为调用已经结束，无法正确等待停用。

异步调用的租约必须保持到任务真正完成。取得 `Task`、排入线程池或向用户报告超时，都不代表调用已经结束。

### 空闲插件

```text
State = Active
活动调用数 = 0
```

表示插件已加载但当前空闲，不表示应卸载插件。只有宿主已经发起停用时，活动调用归零才允许继续 `Shutdown`。

## 4. 停用流程

```text
关闭新调用入口
→ 从新请求路由中摘除贡献
→ 发出取消信号
→ 等待活动调用结束
→ 调用 Shutdown
→ 反注册贡献与宿主事件
→ 清除宿主强引用
→ 卸载加载上下文
```

如果调用未在宿主宽限时间内结束：

- 宿主继续拒绝新调用；
- 已有调用继续持有租约；
- 管理界面可以恢复响应并显示“仍在停止”；
- 宿主继续后台等待；
- 不得提前调用 `Shutdown`；
- 不得强制卸载 ALC；
- 不得用 Full GC 伪造“任务已经结束”。

如果任务始终不结束，宿主可以提示用户重启完成释放。

SPP 不规定宽限时间的固定秒数。当前 StarPie 官方宿主默认使用 5 秒，这是参考实现策略，不是所有 SPP 宿主的强制值。

## 5. `Shutdown` 要求

宿主保证在正常停止流程中，已经没有受宿主管理的插件回调仍在执行后，才调用 `Shutdown`。

插件仍必须释放自己拥有的长期资源：

- 自建后台任务和线程；
- 计时器；
- 文件监听器；
- 宿主和系统事件订阅；
- COM 对象、窗口句柄和其他原生资源；
- 可以重新创建的缓存。

`Shutdown` 必须幂等。插件不得在静态字段中长期保存宿主上下文、贡献对象或宿主委托。

## 6. 加载与停用并发

宿主必须避免同一个插件同时执行：

```text
Load + Load
Load + Unload
Unload + Unload
```

用户停用时，应先关闭会触发惰性加载的启用状态，并在加载临界区内再次检查，避免停用和首次调用交错后重新拉起插件。

插件系统总开关和应用退出可以只停止当前运行时，而保留插件自身的用户启用偏好。

## 7. 错误处理

| 情况 | 处理 |
|---|---|
| 参数无效 | 阻止保存或调用，返回字段错误 |
| 环境不可用 | 返回拒绝/不可用，不计插件缺陷 |
| 用户或宿主取消 | 返回取消，不计普通插件故障 |
| 停用导致取消 | 正常生命周期行为，不计连续失败 |
| 未处理异常或无效结果 | 记为插件故障 |
| 超时 | 记录性能异常，并继续追踪真实任务 |

插件异常不得穿过宿主接缝进入轮盘状态机或 UI 消息循环。宿主负责捕获、记录并按连续故障策略隔离贡献或插件。

## 8. 性能与资源

- 设置页列出功能时读取已注册描述，不逐项执行插件动作。
- 高频事件允许合并和丢弃非关键中间值。
- 动态结构应支持缓存，避免每次打开轮盘都执行磁盘或网络 IO。
- 插件日志必须限速和轮转。
- 不在配置中保存大型对象。
- 日常卸载不得反复执行 Full GC 或强制工作集剥离。

## 9. 安全说明

进程内插件不是安全沙箱。清单中的能力声明用于审核、安装提示和宿主服务门禁，但不能阻止插件直接调用操作系统能力。

不可信插件应运行在独立低权限进程中，再由受信任的进程内适配插件通信。外部通信方式不属于 SPP。

## 10. 官方宿主实现状态

StarPie 当前官方宿主已经实现：

- 按插件包装实例维护活动调用数；
- 加载、卸载和并发首次加载的串行化；
- `Stopping` 状态与新调用门禁；
- Validate、Preview、ExecuteAsync 和旧事件回调的活动租约；
- Background 与超时任务持有租约到真实结束；
- 异步停用和后台继续完成停止；
- 热重载、覆盖安装和卸载等待完全停止；
- 端到端租约与 ALC 回收自检。

这些类名和同步方式属于官方参考实现，不是 SPP 对其他宿主的内部结构要求。详情见 [官方参考实现状态](../implementation/reference-implementation.md)。
