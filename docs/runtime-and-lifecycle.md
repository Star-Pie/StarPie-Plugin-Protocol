# 运行时与生命周期

## 1. 加载流程

```text
静态扫描
→ 校验清单、目标框架和架构
→ 创建独立可回收加载上下文
→ 加载入口程序集
→ 创建插件实例
→ Initialize 暂存注册
→ 验证并统一提交
→ 插件启用
```

扫描阶段不得执行插件代码。SDK 契约程序集必须由宿主共享，不能从插件目录加载第二份。

## 2. 线程规则

- 插件不得假设回调发生在 UI 线程。
- 插件不得直接操作宿主窗口和 WPF 对象。
- 输入 Hook 只负责采集状态，不在其中执行插件代码。
- 交互事件通过独立队列投递。
- 轮盘结构查询不得阻塞轮盘显示；超时使用缓存或静态回退。
- 耗时动作必须后台执行，不能占用动作串行线程。

## 3. 活动调用租约

每次进入插件代码都必须计为活动调用，包括：

- 动作执行及其后台任务；
- 参数业务校验；
- 交互事件回调；
- 轮盘结构查询。

异步调用的租约必须保持到任务真正完成。取得 `Task` 后立即释放租约会导致停用和仍在运行的插件代码发生竞态。

## 4. 停用流程

```text
拒绝新调用
→ 从新请求路由中摘除贡献
→ 发出取消信号
→ 等待活动调用结束
→ 调用 Shutdown
→ 反注册贡献与宿主事件
→ 清除宿主强引用
→ 卸载加载上下文
```

如果调用不响应取消或仍有引用，宿主应显示“需要重启完成”，不能假装已经卸载。

## 5. Shutdown 要求

插件必须释放自己拥有的：

- 后台任务和线程；
- 计时器；
- 文件监听器；
- 宿主和系统事件订阅；
- COM 对象、窗口句柄和其他原生资源；
- 可以重新创建的缓存。

插件不得在静态字段中长期保存宿主上下文、贡献对象或宿主委托。

## 6. 错误处理

插件应区分：

| 情况 | 处理 |
|---|---|
| 参数无效 | 阻止保存或调用，返回字段错误 |
| 环境不可用 | 返回拒绝/不可用，不计插件缺陷 |
| 用户或宿主取消 | 返回取消 |
| 未处理异常或无效结果 | 记为插件故障 |
| 超时 | 记录性能异常，等待真实任务结束 |

插件异常不得穿过宿主接缝进入轮盘状态机或 UI 消息循环。宿主负责捕获、记录并按连续故障策略隔离贡献或插件。

## 7. 性能与资源

- 设置页列出功能时读取已注册描述，不逐项调用插件。
- 高频事件允许合并和丢弃非关键中间值。
- 动态结构应支持缓存，避免每次打开轮盘都执行磁盘或网络 IO。
- 插件日志必须限速和轮转。
- 不在配置中保存大型对象。
- 日常卸载不得反复执行 Full GC 或强制工作集剥离。

## 8. 安全说明

进程内插件不是安全沙箱。清单中的能力声明用于审核和宿主接口门禁，但不能阻止插件直接调用操作系统能力。

不可信插件应运行在独立低权限进程中，再由受信任的进程内适配插件通信。外部通信方式不属于 SPP。
