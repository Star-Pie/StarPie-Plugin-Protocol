# 交互事件路径

## 1. 定位与当前状态

交互事件路径让插件观察轮盘会话，用于音效、触觉、轻量反馈和本地诊断。它是旁路通知，不参与命中和导航决策。

| 项目 | 结论 |
|---|---|
| 当前成熟度 | 旧 Opening/Closed/Language 兼容回调已接入公共租约；统一事件路径尚未完成 |
| 已完成 | 宿主内部路径模块、旧订阅保存、回调租约、停用时撤销订阅 |
| 尚未完成 | 统一贡献接口、事件信封公开契约、有界队列、顺序、节流和背压 |
| 开发建议 | 可以维护旧兼容订阅，但暂不建议第三方依赖新的统一事件路径 |

计划中的 manifest 声明为：

```json
"paths": ["interaction-event"]
```

当前官方宿主尚未正式读取 `paths`，因此该声明目前只是协议目标。

## 2. 当前兼容接口

当前 SDK 提供：

```text
IPluginEvents.OnLanguageChanged
IPluginEvents.OnWheelOpening
IPluginEvents.OnWheelClosed
```

官方宿主已经：

- 按插件 ID 保存 Opening/Closed 处理器；
- 在调用回调前取得宿主内部活动租约；
- 插件进入停止状态后拒绝新回调；
- 停用时撤销该插件的事件订阅；
- 等待正在执行的事件回调结束后再 `Shutdown`。

这些接口仍属于兼容骨架：

- 回调数量少；
- 没有统一事件贡献描述；
- 没有 `SessionId` 和会话内序号；
- 没有有界队列、合并和背压；
- 部分旧回调仍是 UI 线程同步调用。

因此目前不能把它视为完整的 SPP 交互事件路径。

## 3. 计划调用方式

不建议继续为每个事件增加一个 `OnXxx` 方法。计划改为统一事件贡献和事件信封：

```text
插件 Initialize
→ 注册交互事件贡献及所需事件集合
→ 宿主原子提交订阅描述
→ GestureController 在语义状态点产生事件
→ InteractionEventHub 创建不可变事件信封
→ 写入该插件的有界队列
→ 后台按会话顺序取得租约并调用插件
→ 插件完成或异常
→ 任务真实结束后释放租约
```

事件信封至少包含：

| 字段 | 含义 |
|---|---|
| `EventType` | 稳定事件名称 |
| `SchemaVersion` | 事件载荷版本 |
| `SessionId` | 本次轮盘会话 ID |
| `Sequence` | 会话内递增序号 |
| `Timestamp` | 宿主采集时间 |
| `Context` | 前台程序、窗口和鼠标位置等只读上下文 |
| `State` | 可选的轮盘状态快照 |
| `Payload` | 当前事件特有数据 |

计划支持的基础事件：

- `wheel.opening`
- `wheel.opened`
- `selection.changed`
- `level.entered`
- `level.exited`
- `action.committed`
- `action.completed`
- `wheel.cancelled`
- `wheel.closed`

## 4. 投递规则

- 不得在低级输入 Hook 中调用插件。
- 不得在轮盘渲染和命中路径同步等待插件。
- 同一插件、同一会话按 `Sequence` 顺序处理。
- 不同插件互不阻塞，不保证不同会话的全局顺序。
- `selection.changed` 等高频事件可以合并为最新值。
- 打开、提交、取消和关闭等关键事件不得按普通高频规则丢弃。
- 事件回调只观察状态，不能修改扇区、阻止关闭或替换动作。
- 每次事件回调必须纳入宿主活动调用追踪。

后台动作可能晚于轮盘关闭完成，因此 `action.completed` 可以晚于 `wheel.closed`。

## 5. 当前剩余问题

1. **统一贡献接口尚未开放**：现有 `IPluginEvents` 是服务式订阅，不是正式路径贡献。
2. **事件触发点尚未完整接入**：需要在真实状态转换位置发出语义事件。
3. **同步 UI 回调仍有限制**：任意慢插件都可能影响 UI，需要迁移到独立队列。
4. **没有顺序模型**：缺少 `SessionId` 和 `Sequence`。
5. **没有背压**：高频选择变化可能积压并增加延迟。
6. **上下文过于动作化**：现有 `ActionContext` 不足以表达层级、选中节点和关闭原因。
7. **健康度尚未路径化**：事件超时和动作失败需要分开统计。

活动调用租约和停止门禁已经由公共宿主运行时提供，不需要在事件路径复制实现。

## 6. 下一步修改方向

### 第一阶段：稳定事件模型

- 定义统一事件信封、会话快照和关闭原因；
- 定义交互贡献注册，而不是继续增加独立 `OnXxx`；
- 明确关键事件和可合并事件；
- 保持事件只读。

### 第二阶段：实现事件分发器

- 每个插件使用独立有界队列；
- 同一插件默认串行消费；
- 高频事件只保留最新值；
- 回调统一经过公共租约、取消和健康度入口；
- 为异常、超时和队列溢出记录独立结果。

### 第三阶段：接入轮盘状态机

- 在轮盘决定打开、真正显示、选择改变、层级切换、动作提交和关闭位置发出事件；
- 事件数据在状态改变当时复制；
- 不把内部可变对象交给插件；
- 使用音效或触觉插件作为首个验证实现。

### 第四阶段：兼容旧接口

现有 `OnWheelOpening`、`OnWheelClosed` 和 `OnLanguageChanged` 可以继续作为统一事件系统的适配层；新插件应逐渐使用正式交互贡献。

## 7. 开发边界

SPP 1.0 的交互事件路径只允许观察。以下能力不属于这条路径：

- 改变当前命中节点；
- 阻止轮盘关闭；
- 修改当前轮盘结构；
- 替换待执行动作；
- 提交自定义 WPF 控件。

如果未来确实需要插件参与交互决策，应单独设计受控能力，不能通过事件返回值隐式加入核心状态机。
